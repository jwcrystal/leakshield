# 程式碼欄位只在單行普通字串內還原，採啟發式而非語法解析

`code`、`script` 這類欄位（#76；#77 改成單次掃描，行為不變）中，placeholder 只有在**同一行、無插值的普通引號字串內**才會還原；裸 token、`f"{…}"`、`${…}`、`$(…)`、反引號、多行字串、續行與註解中的 token，都會拒絕整次呼叫。判斷方式是逐行的啟發式規則，不做跨語言的語法解析。

這樣定的原因是：「前面有未閉合引號就放行」實測不成立。用原值 `7//2` 測試時，`f"{TOKEN}"` 在 Python 會被當成運算式求值，`${TOKEN}` 會讓 JS 解析失效，`"$(TOKEN)"` 會被 shell 當成命令執行。真正的語法解析器要涵蓋多種語言，成本和新的漏判風險都太高，所以選擇寧可誤擋。被擋時，錯誤訊息會教模型改寫：先把 placeholder 原樣放進單行字串、賦值給變數，再引用該變數。

## Considered Options

- **shadow 模式先蒐集樣本**：被否決。專案沒有蒐集管道，決策也禁止產生 side files，而且蒐集期間缺口會一直開著。
- **變數綁定／工具專屬的 secret binding**：方向正確，但要改工具介面，所以延後處理。

## Consequences

- 已知會誤擋的合法寫法：多行字串內的 token、前面有插值的字串，以及同一行出現 `//` 運算子的程式碼。實際頻率不明，因為目前沒有真實呼叫樣本。
- 未列出的語言結構（例如 Ruby 的 `%q`）可能被誤判。
