# 授權改為 Apache-2.0；不以簽章規則包做商業版

原本是 MIT。評估過「把偵測規則拆成簽章規則包、作為商業版」之後，決定不做，並把授權換成 Apache-2.0。

規則包在技術上可行：manifest 帶版本與規則清單，用 Ed25519 對正規化後的內容簽章，客戶端內建公鑰，載入前驗章、失敗即拒絕。但這裡拆不出有價值的資料層。`src/rules/builtin.ts` 的 29 條規則不是資料：Luhn、IBAN mod-97、帶上下文的信用卡校驗，以及私有網段與 transport 分類，全是程式；能宣告的只有 `custom_rules` 的 regex（上限 200 字元），而那正是最容易被抄的部分。要讓校驗邏輯也變成資料，等於在安全產品裡做一個規則 DSL 與沙箱，自己新增攻擊面。

簽章也只證明來源與完整性，不證明授權：付費者可以原樣再散布。要擋這件事就得有授權伺服器，與「本機掃描、不外傳」的定位直接衝突。

## Consequences

- 0.1.0 到 0.3.0 已以 MIT 發佈，永久可用；新授權只從下一個版本起算。
- npm 一定含 `LICENSE`，`NOTICE` 不是預設項目，所以 `files` 要明列它，否則 Apache-2.0 的標示義務會漏。
- Apache-2.0 比 MIT 多的是專利授權與商標保留，不是防抄；若日後要防商業重用，選項是 proprietary 或 source-available，不是這一步。
- 商業化若發生，位置在企業面（政策管理、稽核匯出、SIEM 整合），與 Apache-2.0 的 open core 相容。
