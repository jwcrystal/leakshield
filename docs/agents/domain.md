# Domain Docs

Single-context repo. Before domain work, read root `CONTEXT.md` and ADRs relevant to the area in `docs/adr/`.

If an ADR directory is absent, proceed without creating one. `/domain-modeling` creates glossary and ADR files only when a real term or trade-off is resolved.

Use the vocabulary from `CONTEXT.md` in specs, issues, hypotheses, and tests; flag any conflicts with existing ADRs rather than silently overriding them.
