# 0.3.0 工具還原：OpenCode v2.2.5 實機驗證

日期：2026-11-06 · OpenCode v2.2.5（Homebrew 版與 OpenChamber 內建 CLI 版本相同）· leakshield 0.3.0（由 OpenCode 自 npm 安裝，`gitHead` 為 `5b9698e`）

## 方法

- **執行方式：** 真實的 `opencode run --standalone --auto`，每次都用獨立的 `XDG_DATA/STATE/CACHE/CONFIG_HOME`，並清除 `OPENCODE_*`／`OPENCHAMBER_*` 環境變數，使用者自己的設定與外掛不會載入。
- **模型：** 本機的 OpenAI 相容替身，依腳本依序回傳工具呼叫，並記錄每個送往模型的請求。**沒有使用真實模型。**
- **外掛：**
  - leakshield 設定為 `{ "package": "leakshield@0.3.0", "options": { "mode": "transparent" } }`，host log 有 `msg="loading plugin" id=leakshield@0.3.0`，快取中的 `package.json` 版本為 0.3.0。
  - 真實的 OpenChamber agent-tool 外掛（`~/.config/openchamber/agent-tool/openchamber-agent-tool`），它的回呼網址 `OPENCHAMBER_AGENT_TOOL_URL` 指向本機替身，token 是假值，所以沒有連到真正的 OpenChamber。
  - 使用者 `rtk` 外掛（`plugins/rtk.ts`）的複本，`rtk` 1.1.0。
- **秘密：** 合成的 `sk-` 金鑰，在送往模型的請求中被換成 `[SGP2:API_KEY-…]` placeholder。工作目錄是一個空的 git repo，讓 `git log` 的錯誤訊息印出它實際收到的參數。
- 測試腳本沒有提交進 repo。

## 結果

| 呼叫 | 結果 | 證據 |
|---|---|---|
| 直接呼叫 `openchamber_render` | host 回報沒有這個工具 | `No tool named "openchamber_render" is currently available`；外掛雖然設定了 `options: { codemode: true }`，在 v2.2.5 上仍只能從 Code Mode 呼叫 |
| `execute` 內呼叫 `tools.openchamber_render({action:"render.page", parameters:{title, html:"…<placeholder>…"}})` | 還原，沒有結構拒絕 | 真實外掛送出的 POST body 中，`html` 是原值 |
| 直接呼叫內建 `question`，`questions[].question` 含 placeholder | 沒有結構拒絕 | 呼叫到達 host，因為非互動執行而被取消，所以看不到工具實際收到的值 |
| `shell`：`rtk sh -c <placeholder>` | 拒絕 | `LeakShield blocked this tool call because the shell command's quoting is not supported.` |
| `shell`：`rtk git log <placeholder>` | 還原 | host log：`message="spawning process" command=/bin/zsh args="[\"-c\",\"rtk git log <原值>\"]"`；git 回報 `fatal: ambiguous argument '<原值>'` |
| `shell`：`git log <placeholder>` | 還原 | rtk 外掛改寫後實際執行的是 `rtk git log <原值>` |

三次執行共 16 個送往模型的請求，**沒有一個含原值**。

## 本機儲存的內容

依 host 資料庫的 `session_message`：

| 工具呼叫 | 存 placeholder 的欄位 | 存原值的欄位 |
|---|---|---|
| `execute` | `state.input.code` | `state.metadata.toolCalls[].input.parameters.html`（內層 render 呼叫） |
| `shell` | `state.input.command` | `state.content[].text`（工具輸出） |
| `question` | `state.input.questions[].question` | — |

原始碼與命令存的是 placeholder，但 Code Mode 內層呼叫的參數和工具輸出都以明文存在本機。從這份 metadata 產生的畫面，很可能會顯示原值。這次沒有打開 OpenChamber 介面確認。

## 沒有涵蓋

- 真實模型：沒有測模型會不會照拒絕訊息改寫。
- OpenChamber 自己的伺服器與介面。
- 使用者環境中的其他外掛（`opencode-observer`、`opencode-cmd-provider`）。
- `curl`／`http` 參數內的 placeholder。
